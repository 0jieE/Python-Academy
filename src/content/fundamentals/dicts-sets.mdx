## Why this matters

"How many times does each word appear?", "Have I seen this number before?",
"How many distinct values are there?" — these questions show up constantly.
A list answers them in `O(N)` per question; a dict or set answers in `O(1)`
on average. That often turns a timeout into an accepted solution.

<KeyIdea>
If you check `x in something` inside a loop, `something` should be a **set**
(or dict), not a list.
</KeyIdea>

## Dictionaries

A dict maps **keys** to **values**:

```python
age = {"ana": 15, "ben": 16}
age["cy"] = 14              # add
age["ana"] += 1             # update
print(age["ben"])           # 16
print("dan" in age)         # False — checks keys
print(age.get("dan", 0))    # 0 — default instead of KeyError
for name, a in age.items():
    print(name, a)
```

Keys must be immutable: numbers, strings, tuples. Lists can't be keys.

## Counting

The most common dict job in contests:

<RunnableExample title="Word frequency" stdin="red blue red green blue red">

```python
words = input().split()
count = {}
for w in words:
    count[w] = count.get(w, 0) + 1
for w in sorted(count):          # sorted keys -> same output every time
    print(w, count[w])
```

</RunnableExample>

`collections.Counter` does the same in one line:

```python
from collections import Counter
count = Counter(words)
print(count.most_common(2))      # [('red', 3), ('blue', 2)]
```

## Sets

A set holds **unique** values with fast membership:

```python
seen = set()
for x in [3, 1, 3, 2, 1]:
    if x in seen:
        print("repeat:", x)
    seen.add(x)

nums = [4, 1, 4, 2]
print(len(set(nums)))            # 3 distinct values
print(sorted(set(nums)))         # [1, 2, 4]
```

Set operations work like math:

```python
a, b = {1, 2, 3}, {2, 3, 4}
print(a & b, a | b, a - b)       # {2, 3} {1, 2, 3, 4} {1}
```

## Cost

| Operation | dict / set | list |
| --- | --- | --- |
| `x in c` | <Complexity time="O(1)" /> average | <Complexity time="O(N)" /> |
| add / update | <Complexity time="O(1)" /> average | `append` is O(1) |
| sorted order | not kept — use `sorted()` | kept |

## Common mistakes

- `d[key] += 1` on a missing key → `KeyError`. Use `d.get(key, 0) + 1`, `Counter` or `defaultdict(int)`.
- `{}` is an empty **dict**; an empty set is `set()`.
- Relying on set order when printing — always `sorted(...)` when the output order matters.
- Using a list as a key — convert it to a tuple first.

## Competition use

- Frequencies → `Counter`.
- "Is there a pair with sum T?" → for each `x`, check `T - x` in a set of earlier values: <Complexity time="O(N)" />.
- Distinct count → `len(set(a))`.
- Ties in "most frequent" problems: sort by `(-count, key)`.

## Exercises

<Exercise title="Distinct values">
Read `N` and `N` integers. Print how many different values there are.

<Answer>

```python
n = int(input())
print(len(set(map(int, input().split()))))
```

</Answer>
</Exercise>

<Exercise title="First repeat">
Read a line of words and print the first word that appears for the second
time, or `NONE` if every word is different.

<Answer>

```python
seen = set()
answer = "NONE"
for w in input().split():
    if w in seen:
        answer = w
        break
    seen.add(w)
print(answer)
```

</Answer>
</Exercise>

<Exercise title="Pair with sum">
Read `N` and `T`, then `N` integers. Print `YES` if two numbers at different
positions add up to `T`, otherwise `NO`. Aim for `O(N)`.

<Answer>

```python
n, t = map(int, input().split())
seen = set()
found = False
for x in map(int, input().split()):
    if t - x in seen:
        found = True
        break
    seen.add(x)
print("YES" if found else "NO")
```

</Answer>
</Exercise>

<Exercise title="Letter histogram">
Read a word and print every letter that appears in it, in alphabetical order,
followed by its count.

<Answer>

```python
from collections import Counter
for ch, c in sorted(Counter(input().strip()).items()):
    print(ch, c)
```

</Answer>
</Exercise>
